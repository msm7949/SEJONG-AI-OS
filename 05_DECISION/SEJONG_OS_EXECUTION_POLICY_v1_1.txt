==================================================
절대 원칙 (ABSOLUTE RULE)
==================================================
AI는 절대 최종 결정을 내릴 수 없다.
모든 결정은 인간(HMN)이 한다.
이 원칙은 어떤 상황에서도 변경되지 않는다.

==================================================
1. WAIT_FOR_SYNC 강제 규칙
==================================================
모든 AI 작업은 반드시 아래 순서를 따른다:

  제안 → WAIT_FOR_SYNC → HMN 승인 → 실행

금지 사항:
- 자동 실행 절대 금지
- 자동 배포 절대 금지
- WAIT_FOR_SYNC 우회 절대 금지
- AI가 HMN 대신 결정 절대 금지

예외 없음. DEV 환경 포함 전 환경 적용.

==================================================
2. AI별 실행 권한 범위
==================================================

[CLD - Claude]
허용: 설계, 문서 작성, 코드 리뷰, 의견 제시
금지: 직접 코드 실행, DB 수정, 배포

[DVN - Devin]
허용: 코드 작성, 테스트, PR 생성
금지: PR 자동 머지, 직접 배포, DB 직접 수정
규칙: 반드시 PR 생성 후 HMN 승인 대기

[CSR - Cursor]
허용: 로컬 코드 수정, 문서 정리, 커밋, PR 생성
금지: main 직접 push, 배포 명령 실행
규칙: 변경사항은 반드시 PR로 제출하고 HMN 승인 후 merge

[GPT - ChatGPT]
허용: 분석, 전략 제안, 구조 설계
금지: 직접 실행 권한 없음

[N8N 자동화]
허용: 알림 발송, 상태 기록, 트리거 감지
금지: HMN 승인 없는 자동 처리
규칙: 모든 플로우는 WAIT_FOR_SYNC 포함 필수

==================================================
3. PR 및 Branch Protection 규칙 (필수 준수)
==================================================
모든 PR은 아래 순서를 따른다:

  PR 생성 (AI)
      ↓
  CI 체크 통과
      ↓
  HMN 리뷰
      ↓
  HMN 머지 승인
      ↓
  머지 실행

금지:
- AI가 직접 머지 금지
- CI 실패 상태에서 머지 금지
- HMN 리뷰 없는 머지 금지
- main 브랜치 직접 push 절대 금지

main 보호 규칙:
- Require a pull request before merging
- Require status checks to pass before merging (CI 3/3)
- Require approvals (최소 1명, HMN 또는 CODEOWNERS)
- Include administrators (관리자 포함 규칙 적용)
- Dismiss stale pull request approvals
- Require linear history

==================================================
4. HMN 판정 등급 (L1~L4)
==================================================

HMN 최종 판단 우선순위는 아래 4단계로 운영한다.

L1 - 즉시 승인 판단 필요 (Critical)
  기준: 사회적·법적·윤리적 영향이 큰 사안
  요구: Forum + HMN 즉시 판단 + WAIT_FOR_SYNC 유지

L2 - 고위험 승인 판단 (High)
  기준: 아키텍처/보안/배포 영향 사안
  요구: 멀티 AI 분석 + HMN 승인

L3 - 일반 승인 판단 (Medium)
  기준: 일반 개발, 문서 수정, 구조 보완
  요구: AI 작업 결과 + HMN 확인

L4 - 단순 승인 판단 (Low/Routine)
  기준: 반복 작업, 경미한 수정, 운영 보조
  요구: 결과 보고 + HMN 확인(필요 시)

참고:
- 기존 LEVEL 5(Routine)는 HMN 판정 단계에서는 L4로 통합 운영한다.
- 자동화는 정책상 보조 기능이며, 최종 실행은 HMN 승인 이후에만 가능하다.

==================================================
5. LEVEL별 처리 규칙 (기존 체계)
==================================================

LEVEL 1 - Critical
  조건: 사회적·법적·윤리적 영향
  처리: Forum 활성화 → 멀티 AI → HMN 필수 승인
  자동화: 절대 금지

LEVEL 2 - High
  조건: 아키텍처 변경, 배포 결정
  처리: 멀티 AI 분석 → HMN 승인
  자동화: 금지

LEVEL 3 - Medium
  조건: 일반 개발, 문서 수정
  처리: AI 작업 → HMN 확인
  자동화: 알림만 허용

LEVEL 4 - Low
  조건: 단순 작업, 버그 수정
  처리: AI 작업 → 결과 보고
  자동화: 알림 허용, 실행은 HMN 확인 후

LEVEL 5 - Routine
  조건: 반복 작업, 로그 정리
  처리: DEV 환경에서만 자동화 허용
  자동화: DEV만 허용, PROD 금지

==================================================
6. N8N 워크플로우 규칙
==================================================
모든 N8N 워크플로우는 아래 구조 필수:

  트리거 감지
      ↓
  Supabase status = WAIT_FOR_SYNC 설정
      ↓
  HMN 알림 발송 (Discord 우선)
      ↓
  HMN 응답 대기 (무한 대기)
      ↓
  HMN 승인 확인
      ↓
  이후 처리 실행

N8N이 자동으로 승인 처리하는 로직 절대 금지.
타임아웃으로 자동 승인 처리 절대 금지.

==================================================
7. RECORD 기록 의무
==================================================
아래 정보는 반드시 Supabase records 테이블에 기록:

- record_id: SEJONG-{AI_CODE}-{YYYYMMDD}-{HHMMSS}-{SEQ}
- 무엇을 수정했는지 (title, content)
- 왜 했는지 (hmn_memo)
- 어떤 AI가 관여했는지 (ai_code)
- HMN 결정 (decision + decided_at)

기록 없는 실행은 무효 처리.

==================================================
8. 긴급 상황 처리
==================================================
시스템 장애 등 긴급 상황 시:

1. 모든 자동화 즉시 중단
2. HMN에게 즉시 알림
3. HMN 직접 개입 대기
4. HMN 지시 없이 복구 작업 금지

EMERGENCY OVERRIDE:
HMN은 언제든 모든 AI 작업을 즉시 중단시킬 수 있다.
어떤 AI도 이 권한을 제한할 수 없다.
