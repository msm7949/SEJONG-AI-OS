목적
이 문서는 SEJONG-AI-OS 시스템의 핵심 제어 엔진인 Router의 역할, 판단 규칙, 선택 기준, 실행 흐름을 정의한다.
Router는 단순 분기 로직이 아니라 Multi-AI Collaboration Framework의 중심 제어 계층이다.

핵심 원칙
- 모든 AI를 동시에 호출하지 않는다
- 필요한 AI만 선택한다
- 위험도와 복잡도에 따라 Single AI 또는 Forum을 결정한다
- Human Verify는 고위험 또는 중요 결정에만 개입한다
- 모든 판단은 Trace로 남긴다

--------------------------------------------------
[1] Router 정의
--------------------------------------------------

SEJONG-AI-OS Router는 사용자 요청을 분석하고
적절한 AI, 실행 방식, 검증 방식, 기록 방식을 결정하는 오케스트레이션 엔진이다.

Router 역할
- 사용자 요청 해석
- Intent 분류
- Risk Level 결정
- AI Capability Map 조회
- Single AI / Forum 선택
- Execution Standby 여부 결정
- Human Verify 필요 여부 판단
- Trace Log 생성

즉 Router는 SEJONG-AI-OS brain 이다.

--------------------------------------------------
[5] Complexity Model
--------------------------------------------------

복잡도 분류

LOW
- 단순 설명
- 짧은 요약
- 명확한 단일 작업

MEDIUM
- 구조 설명
- 비교 분석
- 두세 단계 작업

HIGH
- 설계 결정
- 다중 조건 판단
- 여러 AI 관점 필요

CRITICAL
- 보안 / 권한 / 삭제 / 외부 실행 / 민감 데이터 / 정책 확정

복잡도는 Forum 필요 여부와 직접 연결된다.

--------------------------------------------------
[6] Risk Model
--------------------------------------------------

Risk Level

LOW
- 일반 질문
- 단순 요약
- 위험 없음

MEDIUM
- 문서 정리
- 비교 분석
- 사용자 확인 필요 가능

HIGH
- 보안
- 설계 핵심 변경
- 민감 정보 가능성
- Human Verify 필요

CRITICAL
- 외부 실행
- 권한 변경
- 삭제
- 개인정보/비밀키
- 다중 검토 + Human Verify 필수

기본 규칙
LOW → Single AI 자동 가능
MEDIUM → Single AI + 사용자 확인 가능
HIGH → Single AI 또는 Forum + Human Verify
CRITICAL → Forum + Human Verify REQUIRED

--------------------------------------------------
[8] Execution Mode
--------------------------------------------------

Router는 다음 실행 모드 중 하나를 선택한다.

SINGLE
- 단일 AI 호출

DUAL
- 2개 AI 비교 호출

FORUM
- 다중 AI 토론

STANDBY
- 대기열 유지
- Human Verify 대기
- Router 재판단 대기

VERIFY
- Human 검토 대기

기본 선택 규칙

LOW + 명확한 Intent
→ SINGLE

MEDIUM + 비교 필요
→ DUAL

HIGH + 상충 가능성 / 중요한 설계
→ FORUM

CRITICAL
→ FORUM + VERIFY

--------------------------------------------------
[9] Forum Trigger Rule
--------------------------------------------------

Forum은 아래 조건 중 하나 이상이면 호출한다.

1. 복잡도 HIGH 이상
2. 보안 / 위험 검토 필요
3. 단일 AI 답변 신뢰가 부족
4. 설계 의사결정
5. 상충 의견 예상
6. Human이 직접 Forum 요청
7. Router가 단일 AI로는 부족하다고 판단

--------------------------------------------------
[10] Human Verify Trigger Rule
--------------------------------------------------

Human Verify는 아래 조건에서 필수다.

1. risk_level = HIGH 또는 CRITICAL
2. 외부 실행 / 배포 / 삭제 / 권한 변경
3. 민감 정보 포함 가능성
4. 정책 / 철학 / 최종 결론 확정
5. Forum 합의 없음
6. Human Router가 직접 요구

--------------------------------------------------
[11] Execution Standby Rule
--------------------------------------------------

Execution Standby는 다음 상황에서 사용한다.

WAITING
- 요청 접수 완료, 아직 판단 전

READY
- Router 판단 완료, 실행 가능

RUNNING
- AI 실행 중

VERIFY
- Human 검토 대기

COMPLETE
- 종료 및 기록 완료

REOPEN
- 재검토 요청

Standby는 시스템 과부하 방지, Forum 준비, Human 대기를 가능하게 한다.

--------------------------------------------------
[12] Trace Log Standard
--------------------------------------------------

모든 Router 판단은 Trace로 남긴다.

필수 필드
- trace_id
- user_id
- session_id
- task_id
- selected_ai
- secondary_ai(optional)
- forum_id(optional)
- intent
- complexity
- risk_level
- execution_mode
- verify_required
- standby_state
- reason
- timestamp

예시
trace_id = TRACE-SEJONG-001
selected_ai = GPT
secondary_ai = Grok
intent = ARCHITECTURE
complexity = HIGH
risk_level = HIGH
execution_mode = FORUM
verify_required = YES
standby_state = READY
reason = System design + security review required

- forum_id
